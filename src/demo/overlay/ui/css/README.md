# `src/demo/overlay/ui/css/`

The overlay's one stylesheet. `scripts/build-ui-css.mjs` runs it through Tailwind into
`dist/demo/overlay/ui/overlay.css`; `ui/shadow.ts` injects it into the overlay's shadow root on every surface (demo,
auto, pilot). Storybook (`npm run storybook`, `stories/`) builds the same file on the fly.

- `overlay.css` - the entry: Tailwind's theme and reset, then the files below, then the utilities the builders use.
- `theme.css` - the tokens, after macOS: system colours, label / fill / separator colours, translucent materials, the
  system font and type scale, radii, shadows, motion. Light and dark follow the viewer's setting; `demo.appearance`
  (`WAYGRAPH_APPEARANCE`) pins one with `data-appearance` on `#wg-ui`. The stock Tailwind palette is removed, so only
  these exist. Highlight tones (`data-tone`) map to system colours here.
- `recipes.css` - the few recurring looks as utilities: `material`, `material-thick`, `capsule`, `button`,
  `button-primary`, `button-destructive`, `button-plain`, `field`, `segmented`, `switch`, `icon`.
- `layout.css` - where everything goes: `#wg-ui`, its stage (anchored things) and its chrome slots.
- `ring.css`, `cursor.css`, `fx.css`, `banner.css`, `caption.css`, `chips.css`, `todos.css`, `panel.css`,
  `network.css`, `pilot.css` - one component per file, holding only what utilities can't say: states (`.wg-in`,
  collapsed, behind a ring), keyframes, rules over content another file builds.
- `host.css` - rules for the page itself (the device stage), outside the shadow root; plain CSS, not Tailwind.

How to write overlay UI:

- An element's look is utilities where it is built: `__wgEl("div", { class: "material rounded-panel px-3 py-2" }, ...)`.
  Keep the `wg-*` hook class (code and tests find elements by it) and add the look after it.
- Colours are tokens: `text-label`, `text-label-2`, `bg-fill`, `bg-material`, `text-accent`, `text-red`, ... In a
  component file, read `var(--wg-...)` directly (a `--color-*` variable re-declared on `:host` would not follow
  `data-appearance`). `check:structure` rejects a written colour and a stock palette class.
- Icons are `__wgIcon("check", "text-green")` from `ui/icons.ts` (Phosphor, generated by `npm run icons` from the list
  in `scripts/gen-icons.mjs`), never a Unicode glyph.
- Components layer after utilities, so a state rule (hidden, collapsed) wins over the look it changes.
- Inside the shadow root Chromium ignores `@property`; the build makes Tailwind's fallback defaults unconditional.
