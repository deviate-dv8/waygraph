Block kinds (TypeScript salt)

Three file conventions. One runtime type: Block.

The salt rule

Page*.page.block.tsdefinePageBlockOptional deep-link; hub + methods defineNavBlock, defineEffectBlock, and defineBlock only constrain what you must author (url/click, or requires + instanceOptions, or a free instruction). After build, flows and waygraph auto see ordinary Blocks. Prefer defineEffectBlock over the older alias defineMemEffectBlock.

KindFileHelperSauce Demo example

defineNavBlock nav-login - url: "/"
Nav (click) nav-*.block.ts defineNavClickBlock nav-cart, continue / back
Nav (instance) nav-*.block.ts defineMemNavBlock nav-item-detail - one Open-details row per product
Method *.method.block.ts defineMethodBlock submit-login, finish-order
Effect *.effect.block.ts defineEffectBlock add-to-cart / remove-from-cart
Block (escape) any defineBlock tests / unsure / probes

Effect vs Action

Both live under the route's actions/ folder. Use Effect when the Block mutates a live instance and waygraph auto should list one menu row per DOM match (instanceOptions + mem key). Use Method for forms, submit, logout, and other one-shot business steps without that instance menu.

Navigation stays in Nav

Only NavBlocks may page.goto or encoded nav click. Effects and Actions stay on the page (URL may change as an app side effect of a button - that still is not a Nav).
