Consumer layout

Route folders mirror the app's URL folders — not a parallel invented tree. This is the consumer contract; the engine handout covers the package API.

The rule

App RouterWaygraph blocks
app/page.tsx (URL /) Namespace root: NAV.md + nav-*-root.block.ts — no landing/ folder
app/(auth)/login/page.tsx …/login/ — route groups vanish (URL-invisible)
Folder with no page.tsx Grouping only — no NAV.md, no nav block
app/(app)/layout.tsx (Sidebar) shared/chrome/ — chrome, not a route
app/api/** No UI block

Test: a folder gets NAV.md + a nav block if and only if the app has a page.tsx at that URL.

Block kinds

KindFilepage.goto?Lives
Navnav-*.block.tsYes (url XOR click)Route folder root
Action*.action.block.tsNoRoute actions/
Chrome*.chrome.block.tsNoRoute actions/chrome/ or shared/chrome/

Every route folder with nav or actions must have NAV.md. Namespaces by origin (do not mix): *-web/ for the app FE, *-external/ for MailHog/Mailpit, Studio, probes.

    NAV.md

Do not teach

  • pia-web/root/ or pia-web/landing/ for /
  • shell/nav/… as a second map of routes (sidebar = edges + chrome)
  • Putting Mailpit under *-web/

Same checkpoint + mem

Checkpoint is a phantom tag only — no payload. Same URL after an action ⇒ same Checkpoint; richer mem. act / observe may mem.set / mem.update; resolve is pure; verify Traits cannot read mem. Self-loop via branch + maxSteps; document in that route's NAV.md States / mem-keys.

One-liner: Waygraph maps the app the way App Router maps URLs — one nav (+ actions) per page.tsx, / at the namespace root, mem can change without changing the Checkpoint.
