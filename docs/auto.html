Auto explore

Interactive graph walker: pick the next Block from what is runnable on the live page (Effect Add/Remove, mem-picked Nav Open details, plain Action).

Everything is a Block. defineEffectBlock / defineMemNavBlock / defineNavBlock are TypeScript salt that force requires + instanceOptions (or nav-only shape). The engine does not have a separate Effect runtime.

Commands

WantCommand
Headed picker (default) npx waygraph auto .
CLI menu in the terminal npx waygraph auto . --cli
In-repo Sauce Demo cd examples/saucedemo && npm i && npm run auto

What you see

  1. Checkpoint map: where you are now.
  2. Action list built from the live DOM + Block graph (e.g. one Add to cart row per inventory item via instanceOptions + MemKey).
  3. Hover an option to ring-highlight its target on the page.
  4. Panel chrome: Hide / Show (persisted in localStorage). On narrow viewports the panel is a bottom sheet.

Effect vs Nav (helpers, not engines)

HelperFile conventionUse when
defineEffectBlock *.effect.block.ts Same Checkpoint in/out; mutates page + mem (Add / Remove from cart).
defineMemNavBlock nav-*.block.ts Leaves current Checkpoint (Open item details) - still a NavBlock.
defineBlock *.action.block.ts Ordinary page act (submit login, finish order) with no instance menu.

Alias: defineMemEffectBlock === defineEffectBlock (older name). Prefer defineEffectBlock.

Headed vs headless

ModeHow
Headed explore waygraph auto . (browser + overlay)
Headless tests npm test in the project (no overlay)
Stepper (not auto) waygraph demo shopFlow . - see Demo / step
Try onboarding (temp dir) npx waygraph try demo - copies templates/quickstart

In-repo example

cd examples/saucedemo
npm install
npx playwright install chromium
npm run auto          # headed explore
npm run demo:step     # stepper, manual Next
npm run demo:autoplay # stepper, Auto-advance on
npm test              # headless Playwright suite
