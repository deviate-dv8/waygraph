Detailed source comments

Every showcase Block file opens with a short convention header so the kind, helper, and URL folder are obvious without leaving the editor.

Comment contract

Each *.block.ts / *.effect.block.ts / *.method.block.ts should state:

  1. Kind - Nav | Effect | Action
  2. Helper - which define* salt (or plain Block)
  3. Route - which URL folder owns this file
  4. Why - one line (navigates, instance menu, form submit)

Example shape (Effect)

/**
 * Kind: Effect
 * Helper: defineEffectBlock (TS salt over Block)
 * Route: saucedemo-web/inventory/  (= /inventory.html)
 *
 * Mutates cart for the mem-picked product. waygraph auto lists one
 * "Add ..." row per live Add button via instanceOptions.
 */
export const AddToCartBlock = defineEffectBlock<...>({ ... });

Example shape (Nav)

/**
 * Kind: Nav
 * Helper: defineNavBlock
 * Route: saucedemo-web/  (= /)
 *
 * page.goto lives here only - submit-login Action never navigates.
 */
export const NavLoginBlock = defineNavBlock<...>({ ... });

Example shape (Action)

/**
 * Kind: Action
 * Helper: defineBlock
 * Route: saucedemo-web/methods/  (page URL /)
 *
 * Fills credentials and submits - never page.goto (nav-login owns that).
 * Branches: good creds -> LoggedIn; bad/locked -> LoginPage with error banner.
 */
export const SubmitLoginActionBlock = defineBlock<...>({ ... });

NAV.md per route

Each route folder ships a NAV.md listing URL, nav Blocks, effects/actions, and mem keys / checkpoints. That is the human map; waygraph auto still discovers from compiled Blocks.
